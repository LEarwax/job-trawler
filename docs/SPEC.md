# Job Trawler v2 — Spec

*Draft, 2026-11-12. Replaces the application-bot direction in SPEC.md.*

## Goal

A trawler that finds **fresh** opportunities across many kinds of work and puts them on a Notion board.
The only human step is deciding. No résumé generation, no auto-apply, no email.

### Design rules

1. **You only show up to decide.** Fetching, deduping, scoring and routing run unattended.
   If something needs a terminal command to keep working, that's a bug.
2. **Freshness beats volume.** Every item carries its posted time. Old items are dropped, not ranked lower.
3. **Search types are data, not code.** A new kind of search is a new lane file, never a code change.
   Nothing about the candidate is hardcoded in prompts (v1 hardcoded .NET into `score/fit.py`).
4. **No slop.** The system never writes prose on your behalf. It writes short, specific notes for you to use in your own words.
5. **Failures are visible.** A dead source or a stopped schedule shows on the board within a day. v1 died silently on Oct 16.

## Core concepts

### Profile (`profile/`)

- `profile.md`: plain-language facts about you that every lane can read:
  - 6+ years backend .NET/C#
  - Taught English in Korea
  - Home bartender with real drink-making knowledge
  - Past server and busser
  - Open to most things; **no trades**
- `base_resume.docx`: used only for angle notes (see below).

### Local config (`config.local.yaml`, gitignored; `config.example.yaml` committed)

Anything personal or machine-specific lives here, never in lanes or code:

```yaml
home: "Silver Lake, Los Angeles, CA"   # named location lanes can refer to as `home`
default_radius_mi: 25
notion: { jobs_db: "<id>", system_page: "<id>" }   # tokens stay in .env
```

### Lanes (`lanes/*.yaml`)

A lane is one kind of search. The engine runs every enabled lane on its own schedule.

```yaml
name: bridge-hospitality
intent: >
  Fast-hiring local hospitality work for income now. Bartending first,
  then serving or barback. Values pay, tips, schedule, and distance.
enabled: true
queries: ["bartender", "barback", "server", "cocktail server"]
exclude_keywords: ["line cook", "dishwasher", "CDL"]
geo: { center: home, radius_mi: 25, remote_ok: false }   # "home" resolves from config.local.yaml
sources: [jobspy, craigslist, culinary_agents]
freshness_max_hours: 48
poll_every: 2h
scoring_rubric: >
  9-10: bartender role within 10 mi, posted <24h, pay/tips listed.
  6-8: bartending or serving, reasonable distance, no experience-years wall.
  1-5: requires certs or years you don't have, far away, or not really hospitality.
min_score: 5
hot_score: 8
```

Starting lanes:

| Lane | Purpose | Geo | Freshness |
|---|---|---|---|
| `bridge-hospitality` | Income now: bartending, serving | 25 mi | 48h |
| `core-tech` | Software and AI roles, scored on growth rather than .NET match | Remote + 25 mi | 72h |
| `evolve` | Adjacent: solutions/sales engineer, implementation, AI trainer/evaluator, technical writer, devrel, customer engineer, ESL/edtech | Remote + 25 mi | 72h |
| `experimental` | Generated by the system (see below) | varies | varies |

### Sources (`sources/`)

Every source is an adapter with one interface: `fetch(query, geo, since) -> list[RawPosting]`.
It also declares what it supports (geo radius, posted-since, full description), and the engine works around gaps.

| Source | Covers | Notes |
|---|---|---|
| **JobSpy** (`python-jobspy`) | Indeed, LinkedIn, Google Jobs, ZipRecruiter, Glassdoor | Workhorse for any industry. Supports `location`, `distance` and `hours_old`. LinkedIn rate-limits fast, so keep pages low. Run from a home IP, not cloud. |
| **ATS direct** (Greenhouse, Lever, Ashby public JSON) | A watch list of companies | Freshest data available: postings appear here before the boards copy them. Watch list lives in `watchlist.yaml`. |
| Remote boards (Jobicy, WWR, RemoteOK, HN Who's Hiring) | Remote tech | Reuse v1 adapters. Fix: Jobicy company is always "Unknown"; HN errors silently. |
| **Craigslist** (jobs: food/bev/hosp, etc.) | Local hospitality and gigs | No RSS any more, so this means light HTML fetching of search pages. Low volume and polite. ToS gray area: keep it optional. |
| Culinary Agents | Hospitality | Evaluate: scrape vs. their alerts. |
| JobsPipe API | Aggregated, 30+ sources | Evaluate: has a free key tier and sandbox. |
| ~~Reddit~~ | | Out. RSS ends Nov 13 2026 and the public API closes in March 2027. |

**Non-posting leads.** Some of the best bridge income doesn't show up as postings, for example shift apps like Instawork and Qwick.
These appear as one-time "lead" cards ("sign up for X, it posts bar shifts near you") rather than being polled.

## Pipeline

```
schedule tick (per lane)
  → fetch from lane's sources (since = last successful run, capped at freshness_max_hours)
  → normalize (title, company, location, distance, pay, posted_at, url, description)
  → dedup: url, then (company, title, city) fuzzy, across sources and lanes
  → hard filters: freshness, radius, exclude_keywords, profile hard no's
  → score with Haiku-class model: profile.md + lane intent + rubric + your past feedback
      → {score, one_line_why, pay_extracted}
  → upsert to Notion if score >= min_score
```

Cost: a few hundred postings a day × ~1–2k tokens each with a small model comes to cents to low dollars per day.
The model is configurable.

## Notion (the control panel)

**Jobs** database, one row per posting:

| Property | Type |
|---|---|
| Title, Company | text |
| Lane | select |
| Score | number |
| Why | text (one line, specific: "Posted 3h ago, 6 mi, lists $18/hr + tips") |
| Posted / Found | date |
| Location, Distance (mi), Remote | text / number / checkbox |
| Pay | text |
| Source, Link | select / url |
| Status | New → Interested → Applied → Interview → Closed; Pass; Snoozed |
| Pass reason | select (pay, distance, seniority, not interested, scam, other) |
| Angle | text (filled only after you mark Interested) |

Views:
- **Hot**: score ≥ hot_score and posted < 24h, newest first. This is the "check this now" view.
- **By lane**: a board grouped by lane.
- **Pipeline**: a board grouped by status.

Other databases and pages:
- **Lane proposals**: the experimental lane's suggestions.
- **System**: last run per lane, source health, errors.

Integration with the GTD agent: moving a row to *Interested* creates a task ("Apply: Bartender @ X, posted 3h ago") in the existing Notion task system.

## Assistance without slop

**Angle notes**, generated only when a row moves to *Interested*: 2–4 bullets drawn from the base résumé and profile.
- Which experience to lead with for this posting, and why.
- One transferable story (for example: taught English → training and onboarding).
- One honest gap and how to frame it.
- No full sentences you'd paste. No adjectives like "passionate" or "dynamic". A banned-phrase list is enforced in the prompt and checked after generation.

**Feedback loop.** *Pass* reasons and *Interested* picks are saved as examples.
Each lane's scoring prompt includes your last ~10 decisions in that lane, so it learns your taste without fine-tuning.

## Experimental lane

Weekly job:
1. Read the profile, your recent Interested/Pass history, and a sample of what's being posted across lanes.
2. Propose 3–5 adjacent role types. Each comes with:
   - Why it fits you, in concrete terms.
   - A rough live-posting count near you.
   - 2 example postings.
3. Write the proposals to **Lane proposals**. Setting a proposal to *Accept* generates a lane YAML (as a draft) and enables it.

## Running it

- Runs on the Mac via **launchd** rather than cron. launchd catches up after sleep, and JobSpy works better from a home IP.
- **Heartbeat**: each run writes to the Notion System page. If no run has succeeded in 24h, a row titled "⚠ Trawler stalled" appears at the top of Hot.
- CLI stays for development (`trawl run --lane bridge-hospitality --dry-run`), but day-to-day use is Notion only.
